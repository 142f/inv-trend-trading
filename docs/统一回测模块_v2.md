# 统一回测模块 v2

`inv_trend.application.backtest` 是策略回测的唯一应用层入口。策略证据投影、参数网格、
成交执行、指标统计、滚动验证、参数排名、报告模型和制品发布共享同一份版本化结果。

## 命令

```powershell
strategy-backtest validate-plan `
  --plan config/策略回测计划_BTC_ETH_v2.yaml `
  --source-run outputs/daily_market_scan/runs/2026-08-27/<批次>

strategy-backtest run `
  --plan config/策略回测计划_BTC_ETH_v2.yaml `
  --source-run outputs/daily_market_scan/runs/2026-08-27/<批次> `
  --data-root data `
  --output-dir outputs/backtest

strategy-backtest report `
  --result <批次结果_v1或v2.json> `
  --output <重新生成报告_v2.html>
```

`turtle-daily backtest` 和 `turtle-daily run --with-backtest` 调用相同服务。
`turtle-backtest`、`BacktestService` 和 `StrategyBacktestService` 仅保留一个版本的兼容层。

默认 BTC/ETH 研究计划固定使用 20 日快速入场和 55 日慢速入场，同时启用多头、空头；
滚动训练窗口为 1460 根 D1，验证窗口和步长各 365 根，最终留出 365 根（约一年）。

## 契约与不变量

- `BacktestPlan`、`BacktestSourceBundle`、`BacktestCombinationResult` 和
  `BacktestBatchResult` 当前 schema 均为 v2。
- `execution_result_hash` 只包含订单、交易和权益曲线，用于证明重构前后执行结果一致；
  订单中的随机兼容字段 `intent_id` 不进入业务哈希，新批次会生成确定性的 intent ID。
- `BacktestReportModel v1` 是 HTML 的唯一数据源；浏览器不计算指标、排名、热力图、
  稳定区间或结论。
- 年化收益、Sharpe、Sortino 和 MAR 的统一字段分别为 `annualized_return`、
  `sharpe_ratio`、`sortino_ratio` 和 `mar_ratio`。
- 无法定义的指标为 `null`，原因记录在 `unavailable`，不得用零替代。
- 参数寻优属于研究层，不修改正式策略配置、日报结论、信号或通知。
- `window_boundary_policy` 当前只接受 `mark_to_market`：每个 train、validation 和
  holdout 窗口从空仓、初始资金开始，窗口前数据只用于因果指标预热；窗口末端不虚构平仓，
  结果同时记录 `closed_trade_count`、`open_position_count`、`unrealized_pnl` 和
  `pending_intent_count`，排名的最小交易数门槛使用已闭合交易数。
- `slippage_bps` 当前是从现金扣减的“成本化滑点”，不改变成交价、止损或加仓锚点；
  它不是订单簿或方向相关价格冲击模型。

## 输出

新批次写入：

```text
outputs/backtest/runs/日期/批次/
  01_输入/
  02_参数组合/
  03_汇总导出/
  04_可视化报告/
  05_审计/
```

旧的 `outputs/strategy_backtest`、`outputs/backtest_corrected_v2` 和
`outputs/backtest_legacy_v1` 不迁移、不覆盖，由 `历史回测归档索引_v1.json` 只读索引。
