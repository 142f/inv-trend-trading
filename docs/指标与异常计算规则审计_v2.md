# 指标与异常计算规则审计（daily-indicators-v2）

## 审计结论

本轮审计确认了两个会导致误报或漏报的计算问题，已修正：

1. ATR 分位原先使用最大秩，并列值会被推向分布上缘；常数窗口甚至会被识别为 100% 分位。现改为因果的经验中位秩，并列值使用概率质量中点。
2. 跳空和日内振幅原先与当根 K 线 ATR 比较；当根异常会同时抬高 ATR，从而自我稀释。现改为与前一根已完成 K 线的 ATR 比较。

海龟、SMA、EMA、MACD、ADX/DMI、相对成交量和组合评级未发现公式或未来数据泄漏错误。ADX=25、相对量=1.5、ATR 正常区间=10%–90% 和评级分数门槛属于策略参数，不在没有样本外证据时主观调整。

## 逐项规则与边界

| 项目 | 实际计算口径 | 边界/预热 | 审计结果 |
| --- | --- | --- | --- |
| True Range | `max(high-low, abs(high-prev_close), abs(low-prev_close))` | 首根使用 `high-low` | 正确 |
| ATR(14) | True Range 的 Wilder 平滑，首值是前 14 根算术平均，之后 `((n-1)*prev+current)/n` | 前 13 根不可用 | 正确 |
| Donchian 20/55 | 当根之前 N 根完整 D1 的最高/最低价 | `rolling(N).max/min().shift(1)`；相等不突破 | 正确，无未来数据 |
| 海龟正式信号 | `close > prior_channel_high` 或 `close < prior_channel_low` | 严格收盘确认；`high/low` 越轨只进入观察层 | 计算正确，报告已明示语义 |
| SMA 5/10/20/55/120 | 当根及以前 N 根收盘价算术平均 | 满 N 根后可用；严格递减/递增才算排列 | 正确 |
| EMA 144/169 | `ewm(span=N, adjust=False)` | 虽然 EMA 有初值，但策略到 169 根才就绪 | 保守且合理 |
| MACD 12/26/9 | `DIF=EMA12-EMA26`，`DEA=EMA9(DIF)`，柱体=`DIF-DEA` | 状态至少 34 根，交叉事件至少 35 根 | 正确 |
| D2/D5/D7 MACD | 从固定会话锚点开始聚合 OHLCV，丢弃末尾未完成组 | 仅在高周期 K 线完成后可见 | 正确，无高周期穿越 |
| MACD 组合 | 单周期动量用 DIF/DEA；组合方向使用多周期零轴状态共识 | 零轴多空同时出现为冲突 | 设计可解释，报告已分列显示 |
| DMI/ADX(14) | Wilder +DM/-DM、ATR、DI、DX 和 ADX | 动量相等时 DM=0；ADX>=25 确认趋势 | 公式正确；25 保留为可配置参数 |
| ATR 分位 | `ATR/close` 在含当根的过去 120 根完成 K 线中做中位秩 | 满 120 根后可用；常数窗口=50% | **已修正并列值偏差** |
| 相对成交量 | `volume / SMA20(volume).shift(1)` | 基准不包含当根；基准必须>0；>=1.5 确认 | 正确 |
| 组合评级 | 海龟/SMA/EMA/MACD 四家族定方向，ADX、ATR、成交量做质量调整 | 方向冲突门控为 0；ATR 不在 10%–90% 时 -1 | 算法未改；文案改为“ATR 超出正常区间” |

## 异常审计与修正

| 异常 | 问题 | 修改方案 | 修改理由 | 验证方法 |
| --- | --- | --- | --- | --- |
| ATR 极端分位 | `rank(method="max")` 将并列值放到概率块上沿，常数窗口误报极高波动 | 使用 `(count(<x)+0.5*count(=x))/n` | 对离散或四舍五入序列没有上侧偏差，且保持因果性 | 并列、常数、单调窗口单测；前缀/未来数据不变测试 |
| 跳空 > 2 ATR | 用当根 ATR 会被当根跳空反向抬高 | `abs(open-prev_close) / previous_atr > 2` | 阈值参照在事件发生前已知，不被被测对象污染 | 构造前 ATR=2、跳空=4 的等号边界，严格 `>` 不触发 |
| 振幅 > 3 ATR | 用当根 ATR 会自我稀释异常大振幅 | `(high-low) / previous_atr > 3` | 异常强度和阶段最值均变成可比较的 ATR 倍数 | 构造大振幅样本；3 倍等号边界不触发；前 ATR 元数据可追溯 |
| 异常阶段 | 原始逐日异常会重复刷屏 | 同类型、同上下侧、连续 K 线聚合，原始 ID 保留 | 降噪但不丢证据 | 连续/非连续/恢复状态单测，CSV 原始条数一致 |

所有异常仍仅供报告说明，不进入正式交易通知 outbox。

## 统一数据流与可视化

- `PreparedDailyAnalysis` 一次性产生价格、通道、均线、MACD、DMI/ADX、ATR、成交量与异常比率。
- `InstrumentReportBundle` 只序列化上述列和评估结果；HTML 不重算任何指标、分位或异常。
- 报告中的阈值线从同一 ReportBundle 的 `strategy_snapshot.parameters` 读取，不在 JavaScript 中写第二份策略配置。
- 新增 MACD 柱体、ADX/DMI、ATR 分位、相对成交量和异常 ATR 倍数图；把原先共用量纲不一致的 ATR 分位与相对量拆开。

## 验证要求

1. 公式单测：True Range/Wilder、Donchian shift、MACD、DMI/ADX、中位秩、阈值等号边界。
2. 因果测试：向历史序列末尾追加未来 K 线，既有特征列必须完全不变。
3. 历史对照：比较修正前后的异常、评分和等级变化，保留数据版本。
4. 制品一致性：HTML 内嵌 ReportBundle、JSON、CSV、索引和哈希必须对应同一运行批次。
5. 前端稳定性：绘图脚本语法检查，并验证刷新、resize、折叠、标的切换、图例开关和定位状态。

如需调整 ADX、相对量、ATR 区间或评级分数，应先固化标签与评价指标，在时间分割的走向前向验证中比较基准，不应根据单一 BTC/ETH 截图调参。
