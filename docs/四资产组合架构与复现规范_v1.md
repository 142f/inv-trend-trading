# 四资产组合架构与复现规范 v1

## 范围与身份

核心资产永久固定为 BTC、ETH、XAU、XAG。配置位于 `config/universes/四资产核心_v1.yaml`，版本 1.0。股票研究入口保持兼容，属于工程验证；新组合入口为 `scripts/四资产组合研究_v1.py`。

现有真实来源身份保持不变：BTC/ETH 为 Binance USDT 现货，金属为 external 数据中 Dukascopy 标签的 USD bid 行情。研究执行身份另为 `<symbol>.USD.RESEARCH.UNIT`，不能冒充原交易所产品。

默认 FORMAL 调用必须失败。显式 `--mode RESEARCH_ASSUMPTION` 才能运行合成全额出资单位；这不是正式交易所历史规格。由于原 CFD 历史规格不能确认，正式 ContractSpec 各未知字段保持 null，状态 UNVERIFIED。现有永续分钟引擎不被替换，也不会被错误用于这些现货/CFD 数据。

## Stage 与数据流

新研究流水线：固定来源及版本 → 行情质量 → 因果特征与单资产信号 → 目标风险敞口 → PortfolioAllocationStage → 订单 → execute_open → mark_close → 共享账本 → 评估 → SQLite 报告。

旧 `阶段协议_v1` 的七阶段 Envelope 编解码不修改。新组合采用显式 `PortfolioInput/PortfolioOutput` 类型及数据、特征、分配哈希。新流水线目前是独立组合协调器，没有把组合 payload 注册进旧七阶段编码器，不能宣称旧 Stage CLI 已切换到组合。

PortfolioInput 必须含 run_id、timestamp、asset_signals、asset_volatility、correlation_matrix、current_positions、cash、equity、risk_budget、portfolio_constraints、known_before、lineage。known_before 严格早于 timestamp。

PortfolioOutput 含 target_weights、target_exposures、risk_contributions、cluster_exposures、portfolio_target_volatility、constraint_results、quality、lineage。

## 行情、日历与因果

标准行情包含 instrument_id/timestamp/available_at/OHLC/volume/currency/source/dataset_version/quality_status。Crypto 保留可用扩展字段，不伪造金属 bid/ask、funding_rate 或 open_interest。

读取同一 SQLite 快照的版本指针和金属行；Crypto 读取内容寻址 Parquet 并核对 SHA256。数据版本和读取内容的哈希进入组合版本。副本/版本相异不能仅凭相同文件名复用缓存。

Crypto 日线 open=UTC 零点，close available=下一 UTC 零点。金属仅研究假设 provider date +1 day；因出现周末标签，不能按 Crypto 24×7 或简单周一至周五认证金属会话。

采用 union UTC 日历日。没有 bar 的日期不成交，不伪造开盘；估值沿用最后观测收盘。滚动风险采用该日历日估值收益（休市零收益，复市跳空完整计入），统一 365.25 年化。金属日历缺口分类保持 UNVERIFIED，不把不确定缺失“清洗”为休市。

质量检查：重复、倒序、OHLC、不正价格、非法 volume、时区、可得时点、版本、独立 expected_index 下的缺失/多余会话、连续不变收盘、极端跳空、对象哈希修订。风险窗口排除当前 bar；信号可使用当前已完成收盘，只能下个 bar 执行。

特征缓存键包括 dataset_version、输入 lineage/hash、起止窗口、完整特征配置、code_version。缓存仅构建请求窗口和之前 400 日 warmup；滚动计算不包含未来行。OOS 数据可在锁定后进入协调器的有界数组，账户只收到当前 open，策略只收到当前已完成信号。

## 账户与执行

每策略/压力场景只有一个 100000 USD 初始账户；四资产共享现金。不同策略/压力场景是互相独立的反事实实验，不能相加为实际账户。

维护 cash/equity/available_cash/margin_used/free_margin/realized_pnl/unrealized_pnl/positions/orders/fills/fees/funding/slippage。成本后权益严格满足：

`equity = initial_cash + realized_pnl + unrealized_pnl - fees - funding`。

slippage 已通过成交价计入已实现/未实现损益，不能重复扣除。每个执行/收盘步骤校验上述恒等式。全额出资单位的 margin_used 为持有单位市值，free_margin=现金；不实现真实 CFD 强平、杠杆融资或交易所维持保证金，遇到不支持模型直接拒绝。

先处理降低持仓，再处理增加持仓，共享现金避免超支；同组按 symbol 排序，可复现但存在成交优先级效应。价格按不利方向取 tick；数量向下取 step；现金与预先已知组合权益容量共同限制成交，残量到期，完整保留 PARTIAL/REJECTED。

延迟以各资产实际 bar 计数。缺少金属 bar 时不消费其执行步数。新的目标可替代未执行旧目标，保留 SUPERSEDED 状态。成交时仅见当前 open，不见当日 high/low/close/volume。

研究费用为预声明 fee_bps/slippage_bps；carry 按日历日计算。默认 carry=100bps/year，是合成持有成本，不是历史 CFD 隔夜费或永续 funding。未来资金费事件测试不能替代真实 funding 支持。真实历史 funding 支持仍由原永续认证模块负责。

## 风险分配

Equal Weight、Inverse Volatility、Cluster Risk Budget 三类。集群分为 Crypto(BTC/ETH)、Metals(XAU/XAG)。风险预算通过长仓协方差风险预算坐标解算，不使用全历史最终相关矩阵。

Core+Tactical 将两个 sleeve 分别归一化为单位估计风险，再按 core_fraction 混合，最后执行波动目标和约束；不是固定金额相加。Core=0/.25/.4/.5 进入固定网格。Regime 当前减弱 tactical 信号，对核心 sleeve 的市场分段减仓未单独认证。

single_asset_max_risk 与 cluster_max_risk 的单位定义为“目标年化波动的比例”，即绝对年化波动贡献上限；不声称这是实际总风险百分比。所有结果保存各资产 marginal contribution，集群绝对风险预算约束、单资产权重、gross/max_leverage、波动目标均验收。相关矩阵必须 PSD、对称、对角线1。

实际下一 bar 跳空可能使实现波动或持仓权重超过信号时目标；账户现金始终受限。目标约束不等于全天连续风控保证。

## 策略、Walk-Forward 与实验

策略：Momentum、Breakout（历史高点+ATR buffer、历史低点退出）、Mean Reversion（历史均值 z-score）、Core+Tactical。做空信号不作为实际融券仓位，长仓退出为现金。

预先固定 160 个组合：4类策略×5个波动目标×8个结构化 profile。8个 profile 有绑定参数，明确不是完全笛卡尔网格。参数协议在任何实验前写入 SQLite；不得按 OOS 修改。

2021—2025 五个 OOS 年份；每窗使用前两年 Train。选择 `Sharpe - 2*MDD`，MDD>40%记极低分，同分按 ID。所有 trial（包括异常）写库；选择、训练起止、OOS起止、数据/策略/代码版本及 score 进入不可变锁。

每个候选家族还做固定其它参数的 60/70/80/90/100 lookback 邻域，完全限于 Train；邻域信息不反馈 OOS 参数选择。初始单资产策略筛选仅作训练对照，不改变 Core。

各 OOS 窗口继承现金、持仓、未成交订单及费用；不重置 100000。每窗口账本与账户 checkpoint 写入同一 SQLite。checkpoint 带状态 hash、代码与数据版本；可验证账户恢复一致性。当前 CLI 中断恢复政策是新 study_id 完整重跑，不会续写/覆盖旧参数锁；旧试验保留失败状态。

所有历史标注 replayed_oos；绝不宣称 untouched。pseudo_oos 与 paper_forward 未混用；paper_forward 未运行。

## 基准、风险匹配和压力

单资产 BTC/ETH/XAU/XAG 买入持有；组合初始等权/初始逆波动买入持有；动态 Cluster Risk Budget 和 Volatility Target Passive。买入持有初始95%投入、5%留现金，不再平衡。

风险匹配 passive 每年仅用 Train 的实现波动校准目标并先锁定，再执行下一 OOS 年。公开实际波动差异，不按完整 OOS 方差事后缩放历史收益，也不承诺精确12%等实现波动。

执行压力包括基础、2×fee、2×slippage、额外1/2bar、滑点幅度恶化20%。波动估计×2、Crypto/Metals/全资产相关近1分别属于估计矩阵敏感性；尚非重建联合价格路径的市场压力。此限制阻止正式通过。

统计保存 CAGR/Vol/MDD/Sharpe/Sortino/Calmar/VaR/CVaR/Ulcer/turnover/fees/slippage/funding/持仓时间/gross/net/最长水下天数与是否尚未恢复/最差月季滚动年/滚动Sharpe序列。现金无收益、无风险利率0。

Robustness=SPY+TLT 验证配置已声明；当前 SPY 仅 legacy、TLT输入未认证，保持 NOT_RUN，不得伪造收益或用它们替换四资产。

## 存储与复现

仍使用 `data/metadata/研究目录_v3.sqlite3`。增加 universes、instrument_contracts、portfolio_studies/runs/positions/orders/fills/equity/risk/checkpoints、parameter_trials/locks、walk_forward_windows、benchmarks、stress_tests、reviews/review_scores、lineage、reports。不创建孤立研究库。对证据表建立不可变 UPDATE/DELETE 触发器。

运行（Windows PowerShell）：

```powershell
$env:PYTHONUTF8='1'
.venv/Scripts/python scripts/四资产组合研究_v1.py --study-id core_portfolio_20260909_v2 --mode RESEARCH_ASSUMPTION
```

study_id 必须未使用。正式模式省略 --mode，当前应失败退出。原始数据不随增量 ZIP 复制；ZIP 只交付本次新增/修改的代码、配置和报告，数据库记录留在项目权威库。

最终成功需要补齐真实合同、FX、会话、来源 vintage，完成真实市场联合压力与跨市场输入认证；测试通过不等于这些门禁通过。
