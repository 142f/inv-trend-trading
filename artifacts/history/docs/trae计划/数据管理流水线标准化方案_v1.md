# 数据管理流水线标准化方案 v1

> 目标：把行情数据「获取（下载）→ 转换 → 结构化保存 → 读取」的完整链路**固化为标准、可复用的模块化流水线**，使后续同源/同类数据只写 4 个阶段适配器即可接入，不必重复搭建链路。
> 范围决策（已与用户确认）：**规范文档 + 代码落地**；覆盖范围**仅先标准化 K 线（bars）链路**；兼容底线**逐字节/数值完全等价**（raw/normalized/curated 制品、Manifest、dataset_version、哈希与改前完全一致）。

---

## 1. 摘要

现状：这条链路**已经存在，但整体耦合在单个文件里** —— [api.py](file:///e:/Project/inv-trend-trading/src/inv_trend/data/api.py) 的 `HistoricalDataService` 有 1218 行，把「抓取编排 / 回退、raw 落盘、归一化、合并、质检、发布决策、评审、血缘、catalog」全部揉在一起；`永续历史.py`、`四资产行情_v1.py`、`成分股快照.py`、`时点行情_v1.py` 各自又自建了一套类似链路。这正是"同源/同类数据重复搭建"的根源。

本方案做三件事：

1. **把链路固化成契约**：在 `data` 包内新增 `data/pipeline/` 子包，用 Protocol + DTO 定义标准四阶段（`acquire / transform / persist / read`）与 `PipelineSpec`。
2. **把 K 线链路搬进流水线**：把 `api.py` 中的抓取/转换/保存/读取编排**逐行搬移**到 `data/pipeline/行情阶段_v1.py`，`HistoricalDataService` 退化为薄 facade（公开方法签名不变）。
3. **把"可复用"固化成注册表**：`PipelineRegistry` 以 `kind` 解析 `PipelineSpec`；新数据集只需 `register_pipeline("新kind", 四个阶段实现)`。

产出：目录结构说明 + 四阶段契约 + 分阶段实施步骤 + 扩展指引 + 验收方式（§7）。

## 4. 四阶段标准契约（`契约_v1.py`，decision complete）

```python
"""数据管理流水线的标准链路契约：获取(acquire) → 转换(transform) → 结构化保存(persist) → 读取(read)。"""

PIPELINE_STAGES: tuple[str, ...] = ("acquire", "transform", "persist", "read")

@dataclass(frozen=True)
class DatasetKey:            # 数据集身份
    symbol: str
    timeframe: str

@dataclass(frozen=True)
class PipelineContext:       # 一次链路的上下文（不含任何行情算法）
    kind: str
    key: DatasetKey
    start: datetime
    end: datetime
    run_id: str
    retries: int = 3

@dataclass(frozen=True)
class AcquireOutcome:        # 阶段1 输出
    provider_result: ProviderResult
    raw_path: Path           # raw payload（原始字节）
    raw_frame_path: Path     # raw parsed frame
    errors: tuple[str, ...] = ()

@dataclass(frozen=True)
class TransformOutcome:      # 阶段2 输出（纯计算结果，不落盘）
    normalized: NormalizationResult
    clean: pd.DataFrame
    merged: pd.DataFrame
    conflicts: tuple[dict[str, object], ...]
    rejected_incoming: pd.DataFrame
    quality: QualityReport
    dataset_version: str
    request_id: str
    raw_snapshot_id: str
    outside_window_revisions: tuple[dict[str, object], ...]

@dataclass(frozen=True)
class PublicationOutcome:    # 阶段3 输出
    manifest: Manifest
    status: str
    publishable: bool
    dataset_manifest_path: Path | None

class DataAcquirePort(Protocol):
    kind: str
    def acquire(self, context: PipelineContext) -> AcquireOutcome: ...

class DataTransformPort(Protocol):
    def transform(self, acquired: AcquireOutcome, context: PipelineContext) -> TransformOutcome: ...

class DataPersistPort(Protocol):
    def persist(self, transformed: TransformOutcome, context: PipelineContext) -> PublicationOutcome: ...

class DataReadPort(Protocol):
    def read(self, key: DatasetKey, *, version: str | None = None, start=None, end=None,
             adjusted: bool = True, completed_only: bool = True, allow_research: bool = False,
             allow_legacy: bool = False, min_quality_score: float = 50.0) -> pd.DataFrame: ...

@dataclass(frozen=True)
class PipelineSpec:          # 一个"数据集种类"的完整流水线定义
    kind: str
    acquire: DataAcquirePort
    transform: DataTransformPort
    persist: DataPersistPort
    read: DataReadPort
    rule_version: str = ""
```

**阶段边界铁律（保证逐字节等价）**
- 阶段 2 `transform` **只做计算、不写盘**；阶段 3 `persist` **只做落盘**。搬移时 `write_normalized` / quarantine 写盘从计算段移入 persist —— Parquet 为内容寻址的不可变写，写入顺序不影响内容哈希。
- 两个阶段内**不得改动任何算术、字段顺序、dtype、排序**；搬移只允许改 import 与接收参数（`self.xxx` → 显式注入）。

**注册表（`注册表_v1.py`）**

```python
PipelineBuilder = Callable[[Mapping[str, InstrumentConfig], Mapping[str, BarsProvider], DataLake], PipelineSpec]

class PipelineRegistry:
    def register(self, kind: str, builder: PipelineBuilder) -> None: ...
    def resolve(self, kind: str) -> PipelineBuilder: ...      # 未注册抛 KeyError
    def kinds(self) -> tuple[str, ...]: ...

def register_pipeline(kind: str, builder: PipelineBuilder) -> None: ...
def get_pipeline(kind: str) -> PipelineBuilder: ...
```

**通用编排（`流水线_v1.py`）**

```python
class MarketDataPipeline:
    """标准链路编排：acquire → transform → persist；read 独立入口。dataset-agnostic。"""
    def __init__(self, spec: PipelineSpec) -> None: ...
    @classmethod
    def for_kind(cls, kind, *, instruments, providers, lake) -> "MarketDataPipeline": ...
    def ingest(self, key, start, end, *, retries=3) -> Manifest:   # = acquire→transform→persist
    def acquire(self, key, start, end, *, retries=3) -> AcquireOutcome: ...
    def transform(self, acquired, context) -> TransformOutcome: ...
    def persist(self, transformed, context) -> PublicationOutcome: ...
    def reprocess_raw(self, key, run_id) -> Manifest: ...           # 复用 transform→persist
    def read(self, key, **filters) -> pd.DataFrame: ...
```

**K 线阶段实现（`行情阶段_v1.py`）**：`BarsAcquire` / `BarsTransform` / `BarsPersist` / `BarsRead`，其方法体自 `api.py` 的 `_fetch`、`ingest` 的 raw 写入段、`_ingest_result` 前后两半、`load_bars`/`load_bars_version`/`_strategy_visible_bars` **逐行搬移**；`_completed_bar_changes` / `_same_bar_value` / `_validate_provider_identity` / `_fallback_eligible` / `_group_consecutive` / `_bounded_range` 等纯函数一并搬移。`register_pipeline("bars", build_bars_spec)`。

## 6. 扩展指引（写入规范文档的核心价值）

新增一类同源/同类数据（例如永续、四资产行情）时，只需：

```python
# 1) 实现四个阶段适配器（只写本数据集特有的获取/转换/保存/读取）
class PerpAcquire:        kind = "perpetual"; def acquire(self, ctx) -> AcquireOutcome: ...
class PerpTransform:      def transform(self, acq, ctx) -> TransformOutcome: ...
class PerpPersist:        def persist(self, tr, ctx) -> PublicationOutcome: ...
class PerpRead:           def read(self, key, **filters) -> pd.DataFrame: ...

# 2) 注册
def build_perp_spec(*, instruments, providers, lake) -> PipelineSpec: ...
register_pipeline("perpetual", build_perp_spec)

# 3) 复用同一编排
pipeline = MarketDataPipeline.for_kind("perpetual", instruments=..., providers=..., lake=...)
pipeline.ingest(DatasetKey("XYZ", "D1"), start, end)
```

即：**链路编排（时序、run_id、阶段边界、发布/读取入口）全复用，只有数据特有的 4 段实现需要新写**。

- **D1**：只标准化 K 线链路；永续/四资产/成分股/时点**本轮不迁移**，仅由规范文档给出接入指引（用户已确认）。
- **D2**：新增 `data/pipeline/` 子包而非新顶层包 —— 保证包级依赖图零变化。
- **D3**：`HistoricalDataService` 保留为 facade 而非删除 —— 对外入口与既有调用方（`application`/`adapters`/`cli`/`tests`/`scripts`）零改动。
- **D4**：`_v1` 后缀命名与"代码是权威、文档是解释"的既有约定沿用。
- **D5**：raw 随机 `run_id` 造成的文件名差异属既有行为，等价判定以**内容寻址制品与读回结果**为准，不以目录树字面相等为准。

## 9. 风险与回退

- **风险 R1（等价）**：`_ingest_result` 拆分为 transform/persist 时若误改算术/顺序 → 由 P0 基准 + golden master + 全量回归三重拦截。
- **风险 R2（依赖图）**：子包内新增 import 若跨包 → `test_architecture_boundaries.py` 立即失败（P1 验证点）。
- **风险 R3（调用方）**：搬移符号的引用遗漏 → 全仓库检索（含 `TYPE_CHECKING`/字符串注解/`import_module`）+ `遗留模块引用审计`。
- **回退**：每阶段独立提交，任一阶段失败即 `git revert` 该阶段提交，退回上一可用状态。
