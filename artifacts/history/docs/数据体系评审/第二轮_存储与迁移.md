# 第二轮：存储与迁移 Review

## 发现与修订

- 问题不是 v3 无兼容层，而是 `DataLake`/`Storage` 构造器隐式选后端。
- 新增 `open_data_lake()`、`open_storage()`，后端仅接受 `auto/legacy/v3`；显式
  要求不存在的后端或在 v3 权威上打开 legacy 均拒绝。
- 旧构造器保留一个兼容周期，仅在发生隐式 v3 选择时发出弃用警告。
- v3 初始化登记连续的 1/2/3 Schema 里程碑及校验和；迁移完成前执行完整
  readiness 门禁，未解决 ERROR、破损血缘或缺失 Manifest/质量报告都会阻断。

## 验证

契约、迁移门禁、显式入口和 v3 存储定向测试共 52 项通过。Windows 路径测试改为
`Path.parts` 语义比较。

## 遗留风险

严格 Parquet 解码仍依赖真实 PyArrow；未安装时只能验证存储结构，不能宣告数据
内容最终验收通过。
