# 输出目录

`outputs/` 只保存运行制品，不保存源码或原始行情。日报输出以“运行批次 → 标的 →
结果类型”为权威归档结构；HTML、CSV 和快捷视图都从同一份完整分析 JSON 派生，
不会重新计算策略。

## 日报目录结构

```text
outputs/daily_market_scan/
├─ 输出索引.json                # 当前批次、汇总、latest 和兼容入口导航
├─ runs/<报告日期>/<运行批次>/
│  ├─ 批次索引.json
│  └─ <标的>/
│     ├─ 结果索引.json
│     ├─ 01_canonical/    # 数据更新、策略筛选、趋势决策、完整分析 JSON
│     ├─ 02_report/       # HTML 报告；图表 CSS/JS 内嵌，无外部资源依赖
│     ├─ 03_exports/      # 条件、信号、海龟观察、异常/异常阶段、状态变更 CSV
│     └─ 04_audit/        # 运行清单、配置、血缘、SHA-256 校验
├─ 汇总结果/<报告日期>/<运行批次>/
│  ├─ 全标的_多周期_<日期>_<批次>_汇总报告_v<版本>.json
│  └─ 全标的_多周期_<日期>_<批次>_汇总报告_v<版本>.html
├─ latest/<标的>/         # 最近成功发布的兼容快捷视图及结果索引
├─ state/                 # 信号状态库等可恢复运行状态
└─ <报告日期>.json/html   # 旧调用方使用的日期化兼容入口
```

`runs/` 中的批次不可变，同日重跑必须使用新的运行批次 ID。`latest/`、`汇总结果/`
和根目录日期文件都是可重建的派生视图。

## 命名规范

每个类型目录同时保留固定英文契约名，并提供便于人工定位的描述性文件名：

```text
<标的>_<周期>_<报告日期>_<运行批次>_<结果类型>_v<报告版本>.<扩展名>
```

例如：

```text
BTC_D1_2026-08-20_artifact-retry-1_完整分析_v4.json
BTC_D1_2026-08-20_artifact-retry-1_趋势分析报告_v4.html
BTC_D1_2026-08-20_artifact-retry-1_海龟观察_v4.csv
BTC_D1_2026-08-20_artifact-retry-1_异常阶段_v4.csv
```

程序集成仍可使用 `complete_analysis_result.json`、`trend_analysis_report.html` 等固定
契约名；人工查找从根目录 `输出索引.json` 开始，再打开 `批次索引.json` 和各标的的
`结果索引.json`。

## 其他输出

`us_trend_alerts/` 等独立任务继续保留各自目录。CSV 用于筛选和表格分析，JSON 用于
程序消费与审计，HTML/Markdown 用于人工阅读；同一批次的多种格式属于不同派生视图，
不是重复计算结果。
