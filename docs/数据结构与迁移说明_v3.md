# 数据结构与迁移说明 v3

## 1. 交付结论与边界

工程 **0.3.0rc3**、存储布局 **v3**。交易策略仍为 **滚动策略_v2**、执行框架仍为 **B6**，`production_enabled=false`，没有调参或因收益排序升级策略。

本次实际迁移上传的 `data.zip`：**2,547个来源文件、94,416,549字节**；所有来源原始字节均可恢复，迁移没有修订行情价格或审计结论。以**SQLite作为唯一事务权威**，Parquet和原始响应作为内容寻址对象；不建立MySQL服务、不再按安装环境随机选择第二个Catalog。DuckDB可用于只读分析，但不是另一写入口。

完成**6轮实际迁移和比较**。现有94个head（78 curated、16 legacy）、117个正式/legacy版本、283条采集目录记录均保留。另从已提供附件补入被冻结的**30,503行、10品种研究行情**及**485次B6历史回放摘要、156个参数锁、1,014条训练内排名**；新增信息并非重新回测出来的历史优势。

**验收是分层的：**新存储41个测试通过；发布候选覆盖后实际为568通过、34失败、3跳过，失败集合与v2基线一致；78个当前及固定版本血缘核验通过；固定时段真实回测的数据、7类结果和全部指标相等；另执行13窗口、39次训练内+1次连续样本外回放，280张结果表往返核验通过。**PyArrow未能在本环境安装，未宣称真实Parquet页数据解码/重写测试通过；保留34项原有失败不是“全项目Final”。**

> 包含历史摘要，不包含历史完整账本：485条旧B6记录为 `SUMMARY_ONLY`，完整逐笔/订单/权益明细仍保留在原 `滚动迭代与回测证据_v2.zip`（SHA256已登记）。新数据包不重复携带旧的一次性回放大文件。用户的原归档未被删除。

## 2. 新旧目录与权威边界

旧目录包含 raw、normalized、curated、legacy、manifests、quality_reports、ingestion_reports、dataset_manifests、logs、reference、永续审计，以及根catalog/pointer。新物理结构：

```text
data/
├─ raw/                         # 供应商原始响应；Parquet原样，JSON响应无损gzip
│  └─ <SHA前2位>/数据_<SHA256>.<原扩展名>[.gz]
├─ processed/                   # normalized/curated/legacy行情对象共用CAS，不重复存
│  └─ <SHA前2位>/数据_<SHA256>.parquet
├─ features/indicators/          # 可选的大体积派生时序；一般结构化阶段载荷在数据库
├─ signals/                     # 可选大体积信号附件；信号事实/阶段合同在数据库
├─ backtests/                   # 大体积附件位置；正式回放七表及摘要在数据库
├─ reports/                     # 可再生HTML对象；仅展示，不是指标或结果权威
└─ metadata/
   ├─ 研究目录_v3.sqlite3       # 唯一数据库：目录、参数、结果、账本、版本、审计
   └─ <SHA前2位>/*.parquet      # 已提供的QQQ/SPY参考持仓快照
```

空阶段目录是有意保留的标准入口，不制造无来源的指标、信号或回测数据。文件名采用中文前缀和SHA256；旧logical_path保存在`data_aliases`或`documents`中，不要求旧深层目录实际存在。

**数据库是唯一入口。** 所有需要长期保留的结构化摘要、运行、参数锁、质量与缺口均在库内；必要原始审计JSON字节存入压缩BLOB以保留原SHA，而不是在磁盘创建成百上千个JSON。新运行的七表有标准字段和索引，额外列以安全JSON编码BLOB保存（不是pickle、不是对象代码）。这兼顾可查询与精确恢复原DataFrame，不是仅把ZIP塞进数据库。

旧DataLake/StageStore/Registry继续可调用：v3数据根通过数据库只读适配路径，Parquet路径解析为真实对象文件；旧数据根保持v2行为。旧的**显式导出**可用于人读和第三方工具，但导出不得反向覆盖数据库。此包不擅自删除项目根`outputs`或`processed_data`中用户未上传/未确认的文件；除冻结研究CSV外，其他旧CSV来源不被伪称已整体迁移。

## 3. 数据关联、主键、时间与格式

`object_id`及原文`sha256`均为原始未压缩字节的64位十六进制SHA256；`stored_sha256`是实际压缩/存储字节SHA256，两者不能混用。物理文件路径在库内均为相对data根路径，无运行机器绝对路径依赖。

`dataset_versions.version`保留原不可变版本ID，`parent_version`建立父版本关系；`dataset_heads(symbol,timeframe,channel)`保存当前版本和CAS修订号。旧`current_versions`只是同一事务内维护的兼容投影，不再有磁盘pointer与第二库的双重权威。正式激活同时核验对象、质量报告、Manifest身份、行数和版本；激活、兼容head、rollback、审计在一个`BEGIN IMMEDIATE`内提交。

`studies_v3`标识冻结的研究协议，`result_runs`标识实际回放或历史摘要，`study_runs_v3`建立外键关系；`wf_windows_v3`按研究/迭代/窗口关联参数SHA及锁定原文，`candidate_rankings_v3`保留全部训练内排名，不按外层收益筛选。`result_metrics`用run/window/instrument/metric复合键，`result_rows`用run/table/ordinal复合键。`runs`与其配套表是既有通用阶段发布/Experiment Registry的兼容合同，`result_runs`是回放实例，二者不是复制同一运行的两个事实库。

新生成的时间字段为带时区ISO8601 UTC；窗口要求 `train_start < train_end < test_start < test_end_exclusive`。`source_time`和审计原文保留供应商原始标注，不把未知时区伪造成UTC。原始市场`date`不改写，B6仍按原合同推导开盘/收盘事件。本次没有补造`available_at`、交易日历、复权、借券或盘口认证。

SQLite金额/价格/指标使用REAL，延续v2浮点模型，不擅自改变为Decimal导致交易数量或结果漂移；原始JSON和DataFrame哈希用于一致性核验。数量、金额单位继承品种合同，成交量单位不因迁移而获得可执行性认证。状态`RESEARCH_ONLY`、`LEGACY_ONLY`、`DOWNLOAD_ERROR`、`SUMMARY_ONLY`原样保留。

Parquet源文件全部保持字节不变，不重新分桶/合并row group；检查了真实Parquet页脚、Schema和行数元信息，但缺少PyArrow页解码验证。原始JSON响应使用`gzip(mtime=0)`无损压缩。小型审计原文使用zlib；回测逐行记录另存索引列和类型恢复信息。固定研究CSV原文压缩入库并与`market_bars_v3`的30,503行独立验指纹，因此即使本地不再有该CSV，标准滚动入口仍可读取冻结输入。

## 4. 阶段输入/输出合同

|阶段|标准输入|标准输出/权威|读取接口|
|---|---|---|---|
|raw|原始供应商响应、请求/来源身份|原始对象+data_aliases+审计事件|UnifiedStore.read_bytes/resolve|
|processed|raw对象、清洗规则、质量检查|Parquet对象、dataset_versions/heads、quality_assessments|DataLake/Repository；固定版本血缘接口|
|features/indicators|锁定dataset_version、参数、父stage_id|StageStore合同/载荷；必要大时序对象|StageStore.publish/load|
|signals|指标父制品、策略规则、时间边界|统一阶段事实、信号/证据载荷；不重算历史父输入|StageStore及共享Storage|
|backtests|研究协议、训练参数锁、点时行情|result_runs/metrics/tables/rows、wf_windows、candidate_rankings|ResultRepository.read_table、SQL视图|
|reports|已完成回放七表和冻结摘要|HTML派生对象+对象哈希/逻辑引用|滚动报告及UnifiedStore.resolve|
|metadata|以上每次操作和来源关系|版本、质量、审计、来源清单、结构版本、六轮记录|只读SQL/UnifiedStore|

一次新回放保存“权益曲线、交易记录、订单记录、分笔明细、资金流水、策略证据、品种归因”七张结构化表。支持DataFrame/Series、空表、RangeIndex、时区、频率、原列类型及object列None/NaN/NA/NaT；恢复时核验表SHA及内容指纹。CSV兼容读取仅在内存生成，不产生长期CSV副本。

## 5. 删除、迁移、保留和清理

**删除的是物理冗余，不是证据：**1743个原文件对象去重后为1706个唯一对象，合并**37个完全相同的物理副本**，原逻辑引用全部保留；804个散落元数据/日志/目录快照收入SQLite，不再逐个留在磁盘。原目录catalog原始字节也作为压缩审计原文保留，但不是第二个活动数据库。源数据的任何独有版本未按日期或文件名批量删除。

源Manifest存在**95条既有缺失引用**；迁移记录为`SOURCE_REFERENCE_MISSING`，没有补造不存在的文件、哈希或审批，不将“缺失”转换成“无问题”。这些引用不等于95个唯一文件。当前78个curated血缘均可核验，不能由此推导旧历史所有缺失引用已经解决。

B1—B5历史试验文件、旧单次账本、图片截图和临时结果不进入新的data；只补入B6必要摘要/冻结协议/参数锁，并登记原外部归档SHA。原附件不改动。测试时生成的40次新回放只用于独立验收目录，不进入交付data，最终库中的历史回放仍清晰标为SUMMARY_ONLY。

生命周期：采集→不可变对象→质量/Manifest→同库激活→引用保护→显式退役/清理审查。默认清理为dry-run，只枚举至少7天、未登记且符合临时命名的失败写入残留；任何source_inventory、版本、参数、结果、审计或已登记对象都不由该命令删除。此版**不自动回收独有历史正式数据**。跨阶段删除正式记录需新增经批准的保留策略，不能依靠“看起来旧”判断。

SQLite备份使用在线backup API，不通过复制正在写入的主文件代替一致性备份。该命令只备份数据库；完整恢复必须同时保留所有被引用的不可变对象。不得仅复制WAL模式下的主文件、忽略尚未checkpoint的写入。移除旧data前应整体备份并停止所有写入；原文件只读迁移，失败目标留下FAILED状态，不会被当作可替换版本。

单位MB为10^6字节；耗时ms为暖OS缓存下独立微基准中位数，7次读取/查询、5次100条写入；原始样本保留在数据库和证据包。第1—5轮原样保留当时统计口径，可能含32KiB SQLite共享内存边车；第6轮显式排除临时边车。第4—6轮包含额外冻结研究材料，不能把增加覆盖范围产生的空间当纯压缩退化。

第6轮微基准空间92,287,348字节；追加必要交付审计后当前为**92,352,884字节**（最终精确值和ZIP大小以交付校验清单为准）。相较原data空间仍下降，且补入了冻结行情/历史摘要；文件数由2547降至1707，减少32.98%。质量聚合查询约**20.84倍**快，100条批量写入约**2.26倍**快。查询结果逐项相等，不用不同任务制造提速。

**ZIP体积与解压空间分开：**原data.zip约43.19 MB，新交付ZIP约47.2 MB；新增研究行情、历史摘要及审计资料后，下载包体积增大约9%，不宣称压缩包也变小。最终精确大小见外部交付校验清单。

**保留负面结果：**单份审计原文提取由约0.0058ms变为0.7770ms，数据库连接/查询、解压和SHA复核增加开销；第6轮比第5轮的个别微基准也慢，关系表和审计检查增加复杂度。它不是所有I/O指标都优于文件系统的方案。业务聚合查询、空间/文件治理和事务一致性改善，不能宣传“全项零退化”。Parquet样本字节读取为0.005979→0.005969ms，仅说明字节保持且本机微基准近似，不是解码加速或回测提速证据。第6轮迁移本身与全量测试同时执行，9.056s不可作为无负载性能排名。benchmark_rounds.started_at由证据文件mtime减实测耗时估算，metrics_json明确标记该依据，不充当可信外部时间戳。

## 7. 正确性、兼容性和实际执行

原始v2全项目：527 passed / 34 failed / 3 skipped。最终新增存储41个用例通过；覆盖后全量：568 passed / 34 failed / 3 skipped。失败集合不增加、不修改旧测试以换通过率；两者日志和失败ID对比保留。34项包含缺失PyArrow以及原有日报/制品合同问题，未借本次存储任务虚报修复。

真实回测采用冻结v4参考规则/B6，2025-01-01至2026-04-21（结束不含），旧CSV与新库10个品种DataFrame指纹完全一致；权益、交易、订单、分笔、资金、策略证据、品种归因7类结果和全部指标相同；数据库往返精确相等。另以最终源码在独立覆盖项目执行13个窗口、39次训练内回放+1次连续样本外回放，并恢复/核验280张结果表和13个参数锁；基准收益仍**31.4939105815071%**，最大回撤**18.0186013811243%**，Sharpe **0.3794780785531528**。这是存储兼容性验证，不是新策略盈利证明，不选择候选09/11或更有利的交易假设。

核验含：全部来源字节相等、数据库integrity_check/foreign_key_check、对象/原文SHA、审计哈希链、数据库head与旧Catalog一致、78条当前与固定版本血缘、485条历史摘要/156锁、并发写入、过期CAS、幂等重试、质量/对象错误绑定拒绝、提交前故障回滚、RangeIndex/空表/缺失值恢复、路径穿越、老文件影子覆盖拒绝、安全清理和异地数据库恢复。

环境Python 3.13.5、SQLite 3.46.1，Linux本地文件系统。**PyArrow、DuckDB与Ruff安装受网络/DNS限制未成功**；没有使用伪Parquet兼容层。真正Parquet解码、Windows文件锁、网络盘并发、真实API采集及全项目Final仍须在目标环境验收。

## 8. 本地替换/迁移步骤

### 8.1 本地数据与附件一致：整体替换

先停止所有采集、研究和报告写入；备份原代码与原data。将补丁解压到独立目录，先执行只读冲突核验：

```bash
python 补丁目录/scripts/覆盖前核验_v3.py --root 本地项目 --manifest 补丁目录/docs/补丁文件清单_v3.json
```

只接受BASELINE_MATCH或ALREADY_APPLIED；出现CONFLICT先人工合并。然后覆盖代码补丁，将旧`data`改名备份，再把`完整数据_v3.zip`解压到项目根，使路径为`项目/data/metadata/研究目录_v3.sqlite3`。**不要把新旧data混合解压，也不要变成data/data。**

```bash
cd 本地项目
python scripts/数据目录管理_v3.py verify --data data
python scripts/数据目录管理_v3.py summary --data data
python -m pytest -q tests/test_结构化存储_v3.py
# 必须安装真实PyArrow，不能以第一条字节核验代替这一条：
python scripts/数据目录管理_v3.py verify --data data --strict-parquet
```

完整依赖沿用pyproject，可在可联网目标环境使用`python -m pip install -e ".[test]"`，再执行全量pytest；不要跳过错误后宣布Final。由于全项目本来存在34项失败，目标环境结果需独立核对，不保证仅安装PyArrow就能清零所有失败。

### 8.2 本地data在附件后又有新增：不要盲目覆盖

对最新本地旧目录重做迁移，来源只读，目标必须不存在且不在来源内部：

```bash
python scripts/数据目录管理_v3.py migrate --source data --target 数据迁移候选_v3 --research-data 核心代码与训练验证测试数据_20260907.zip --evidence 滚动迭代与回测证据_v2.zip
python scripts/数据目录管理_v3.py verify --data 数据迁移候选_v3 --strict-parquet
```

也可直接把`--source`设为原`data.zip`。源ZIP要求唯一明确data根，拒绝路径穿越、符号链接、重复路径及超过预设大小的包。来源已经是v3时禁止重复按旧格式迁移，应使用备份/恢复。核验通过后停止写入、备份旧data，再把候选目录整体改名data。缺少补充附件时只迁移原data；不会制造冻结CSV或历史摘要，正式研究入口会明确报告缺少输入。

### 8.3 正式研究和清理

```bash
# 默认完整冻结候选协议；参数和逐Bar逻辑仍是v2/B6
python scripts/结构化研究_v3.py --study 冻结研究_v3
# 存储烟测：仅固定参考候选，一轮；不是完整策略比较
python scripts/结构化研究_v3.py --study 存储烟测_v3 --iterations 1 --candidate-limit 1 --skip-stress
python scripts/回放制品核验_v2.py data/backtests/存储烟测_v3
# 默认只读计划
python scripts/数据目录管理_v3.py clean --data data

```

```sql
CREATE VIEW v_backtest_summaries AS
 SELECT r.run_id,s.study_id,r.logical_path,r.status,r.strategy_version,r.scope,r.data_version,r.code_hash,
 r.parameter_hash,m.window_id,
 MAX(CASE WHEN m.metric_name='total_return' THEN m.value END) total_return,
 MAX(CASE WHEN m.metric_name='annualized_return' THEN m.value END) annualized_return,
 MAX(CASE WHEN m.metric_name='max_drawdown' THEN m.value END) max_drawdown,
 MAX(CASE WHEN m.metric_name='sharpe_ratio' THEN m.value END) sharpe_ratio,
 MAX(CASE WHEN m.metric_name='calmar_ratio' THEN m.value END) calmar_ratio,
 MAX(CASE WHEN m.metric_name='trade_count' THEN m.value END) trade_count,
 MAX(CASE WHEN m.metric_name='win_rate' THEN m.value END) win_rate,
 MAX(CASE WHEN m.metric_name='payoff_ratio' THEN m.value END) payoff_ratio,
 MAX(CASE WHEN m.metric_name='profit_factor' THEN m.value END) profit_factor,
 MAX(CASE WHEN m.metric_name='fee_cost' THEN m.value END) fee_cost,
 MAX(CASE WHEN m.metric_name='slippage_cost' THEN m.value END) slippage_cost,
 MAX(CASE WHEN m.metric_name='carry_cost' THEN m.value END) carry_cost
 FROM result_runs r LEFT JOIN study_runs_v3 s USING(run_id) LEFT JOIN result_metrics m USING(run_id)
 GROUP BY r.run_id,m.window_id;
```

## 12. 最终裁决

这是**存储结构化与兼容性改进版本**，不是新交易策略。以本次附件为基线，正式来源可恢复、当前版本可追溯，物理重复/碎片减少，业务批量查询与批量写入提升；单文档原文访问存在明确退化。不能用新目录替代市场执行认证，也不能把旧历史通过迁移变成未见样本。

交付前后SHA256、最终字节数、补丁逐文件清单、完整测试日志/失败集合、6轮原始测量、ZIP完整性与异地恢复记录另见《交付校验清单_v3.json》《存储重构验收证据_v3.zip》。证据包与生产data分离，避免将一次性验收运行重新塞进长期数据目录。
