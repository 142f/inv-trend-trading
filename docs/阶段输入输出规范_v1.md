# 统一 Stage 输入输出规范 v1

状态：已实现并测试的 **D1 股票/ETF、只做多现金研究链路**。本文描述真实代码，不把原项目所有旧流水线视为已迁移。不支持以本规范推定实盘准入。

## 1. 目录、依赖方向与唯一权威

```text
src/inv_trend/
  core/阶段协议_v1.py                 不可变协议、序列化、哈希、类型边界
  core/在线策略_v1.py                 有界在线特征、三方法、36组网格
  core/事件账户_v1.py                 逐事件订单、现金、成交约束
  data/时点行情_v1.py                 版本固定、只读快照、时间水位数据库游标
  application/标准阶段_v1.py          七个独立run及snapshot/restore
  application/多方法研究_v1.py        冻结协议、滚动训练/锁参/回放编排
  application/研究评分_v1.py          训练选择、样本外汇总、八维评分
  storage/阶段运行_v1.py              原v3数据库内的增量Stage表及事务
  storage/研究核验_v1.py              锁参、账本、哈希、指标口径独立复算
  observability/研究评审_v1.py         数据库结果的HTML投影，无策略计算
  cli/分阶段研究_v1.py                study/stage/verify/report
  cli/存储治理_v1.py                  复用已有v3治理实现，不创建第二权威库
```

依赖方向：`core ← data/storage/application ← cli`；HTML位于observability，由CLI组合。core不导入IO、数据库、应用层；application不导入CLI或展示层。原有6项架构边界测试继续约束这些规则。

既有 `application/strategy_backtest` 是兼容转发入口，不再另造实现；保留原Turtle、日报和多资产接口，不将其悄悄替换为新策略。旧 `research/d1_suite/scripts/d1_backtest_common.py` 的CSV加载由两次读取改成一次，返回字段、排序、UTC索引保持不变；它仍是离线旧研究入口，不能当作本轮因果回测证明。

长期权威仍为 `data/metadata/研究目录_v3.sqlite3`。行情文件继续保留在已有 `data/raw`、`data/processed` 内容寻址对象区；本链路读取既有 `market_datasets_v3/market_bars_v3` 固定版本。指标、信号、回测、评估和报告属于**逻辑层级与数据库类型**，不强制复制为七套实体文件目录。

```text
逻辑数据生命周期：raw → processed → features → signals → backtests → reports
全程横切：metadata / versions / quality / lineage / parameter locks
```

`processed_data` 仍有旧消费者，故列为兼容受保护数据区，不因目录名字旧就删除。数据库中已登记的数据对象、行情及审计记录不能仅靠“看起来重复”判断是否可删。

## 2. 公共协议

接口：`stage.run(input) -> Envelope[Payload]`；有状态Stage额外实现 `snapshot() -> dict`、`restore(state)`。外部独立执行用 `run_checked(stage,input)`，异常后恢复执行前状态，返回结构化FAIL；完整研究驱动遇错终止当前研究并记失败回执，不将失败窗口计为成功。

七阶段首端从typed `RawBar`进入；其余阶段均直接消费上游Envelope。Envelope嵌套上游必需数据，故不需要隐式全局DataFrame、临时CSV或临时JSON串联。实例只处理一个run及一个标的时间流；更换参数、代码、数据版本或标的必须新建实例/run，或使用显式已验证检查点。

### 2.1 Envelope必填字段

| 字段 | 类型 | 约束及意义 |
|---|---|---|
| context.run_id | str | 不为空，标识一次阶段链；研究驱动含研究/标的/方法/窗口/场景 |
| context.dataset_version | str | 固定行情版本，不能用“latest”代替 |
| context.strategy_version | str | 当前为在线三方法版本；不是收益排名 |
| context.code_version | str | 按相对路径与内容计算的src/inv_trend Python源码SHA-256 |
| context.parameters_hash | str | 参数绑定摘要；完整研究包含候选参数、执行配置及锁记录摘要 |
| context.scope | enum | TRAIN/OOS/STRESS/TEST/RESEARCH_ONLY；无LIVE值 |
| stage | enum | acquire/process/indicators/signal/backtest/evaluate/report |
| stage_version | str | 当前1.0；实现不兼容变更须升级并显式迁移 |
| schema_version | str | 当前1.0；未知协议版本拒绝解析 |
| payload | typed object | 下表对应的冻结dataclass |
| generated_at | UTC ISO8601 | 实际生成时间，不代表市场信息可知时间 |
| as_of | UTC ISO8601 | 本次决策所知行情的时间水位 |
| input_hash/output_hash | str | 上游payload摘要/本payload摘要；源记录input_hash为空 |
| parent_ids | tuple[str] | 上游制品ID；数据库外键保护直接父节点 |
| quality | Quality | PASS/WARN/FAIL、checks、errors、warnings |

时间严格使用UTC且必须显式携带时区；市场日标签不等于可交易/可知时刻。`artifact_id`覆盖context、阶段、版本、payload哈希、父节点、质量及市场时间，不含生成墙钟，支持同内容幂等。内容、版本或质量不同不会冒用同一ID。

类型实现：冻结dataclass + 显式JSON编码/解码；JSON仅用于数据库内结构化列及外部只读导出，不用散落文件承担阶段交换。拒绝未知payload类型、未知顶层字段、缺失必要payload字段、哈希不符和跨run交换。浮点不可为NaN/Inf；行情必须满足OHLC边界，volume非负。

FAIL输出的payload为 `StageFailure(code:str,message:str,retryable:bool)`，quality.errors非空；可入库审计，但下游正常run必须拒绝。WARN用于预热不足、研究级数据、受限做空及未完成市场认证；PASS只表示已列出的本阶段检查通过，**不等于上游数据被认证，更不等于可实盘**。

### 2.2 参数与状态

候选 `Candidate`：family、lookback、threshold、exit_lookback、max_weight、target_volatility；执行 `ExecutionConfig`：initial_cash、fee_bps、slippage_bps、delay_bars、volume_participation、lot_size、max_weight。均有类型/数值范围检查。

完整研究的配置在冻结protocol、candidate表、window lock及checkpoint中保存。独立CLI从上游参数哈希或经过摘要验证的检查点解析配置，不静默选默认策略；显式候选与上游冲突、配置检查点损坏或代码版本不同均拒绝。直接Python组合由调用方显式注入Candidate与ExecutionConfig，测试及策略替换不依赖CLI。

检查点必须保存run context、策略持仓方向、指标历史有界队列、账户现金/仓位/累计费用/未成交队列、评价在线统计状态。恢复核验配置及摘要；同一run/stage/as_of状态不能被覆盖为另一个值。现有CLI支持指定时刻恢复单Stage；**整项研究崩溃后的调度器自动续跑尚未实现**，失败研究保留证据，重新验证使用新的study_id。

## 3. 七阶段逐项定义

| Stage | 输入与来源 | 输出Payload与主要字段 | 校验/状态 | 时间粒度 |
|---|---|---|---|---|
| acquire | 版本固定Repository产生RawBar | RawBar(symbol,timeframe,source,opened_at,available_at,OHLCV,sequence) | 来源记录收到；研究数据WARN | 单根已完成D1 |
| process | acquire/RawBar | Bar：同名字段，UTC规范化、数值和顺序已验证 | 有限正OHLC、非负量、同标的严格递增；不静默填补/删行 | 单根D1 |
| indicators | process/Bar + 显式Candidate | FeatureFrame(bar,values,ready,state_hash,parameters) | 预热不足WARN，否则本地因果计算检查通过 | 单根D1 |
| signal | indicators/FeatureFrame + Candidate | Signal(features,direction,target_weight,candidate_id,evidence) | 指标/策略参数错配拒绝；做空目标WARN | 收盘信号 |
| backtest | signal/Signal + ExecutionConfig + AccountState | AccountSnapshot(symbol,as_of,cash,quantity,close,equity,initial_cash,fees,slippage_cost,fills,pending_orders,signal_hash) | 资金、仓位、延迟与上一日流动性约束 | 开盘成交→收盘估值 |
| evaluate | backtest/AccountSnapshot | Evaluation(as_of,metrics,quality_gate,production_enabled=False) | 在线收益统计；完整研究另做多参数/多窗汇总；研究WARN | 每根D1增量 |
| report | evaluate/Evaluation | Report(as_of,title,metrics,verdict,production_enabled=False) | 沿用评价状态，不重算信号 | 同as_of |

### 3.1 行情、指标和信号字段

RawBar/Bar：symbol/source/timeframe为str，timeframe固定D1；opened_at/available_at为UTC字符串且开盘早于完成时间；open/high/low/close/volume为有限float；sequence为非负int。

FeatureFrame.values为有序键值对：`momentum, channel_high, channel_low, exit_high, exit_low, zscore, volatility`；预热不足时值可为None且ready=False。parameters含lookback与exit_lookback，防止传错同形异义指标。features.bar保留此根行情，信号不需要第二个未声明行情输入。

Signal.direction为-1/0/1，target_weight为[-1,1]有限数，方向与权重符号一致。evidence记录方法、候选ID、观察水位与触发原因。三方法的负向信号保留，但现金执行不借券，负向目标降为零仓位；不是可做空回测。

### 3.2 成交与评价字段

Fill包含order_id、signal_at、filled_at、requested、quantity、price、fee、slippage_cost、status、reason。quantity是带方向的实际成交股数；requested是带方向请求量；fee/slippage_cost是非负金额；FILLED/PARTIAL/REJECTED均保留。无变化目标不伪造交易；fill_count仅统计实际非零成交，不是完整开平仓笔数。

AccountSnapshot的fees/slippage_cost为账户累计成本；Evaluation的窗口成本减去该窗口开始前累计成本，避免跨窗重复计费。总收益、年化收益、最大回撤、Sharpe、成交次数、费用、滑点、终值与bars与研究汇总共用 `D1_CLOSE_252`口径，并有逐字段回归测试和落库复核。

收益以初始资金和日收盘权益计算；首日损益计入回撤；Sharpe使用rf=0与252个交易日，现金无利息；没有末端强制平仓、税费或分红现金流。持仓按末日收盘估值，尚未到期订单仍保留。不将日收盘回撤解释为盘中最坏回撤。

## 4. 严格时间推进与Walk-Forward

每个半年窗口执行以下顺序，而非读完整测试矩阵再选参数：

```text
读取当前窗口之前最多887根已知行情（只读快照、有上限）
→ 最后5根不参加选参；126根预热 + 756根训练 = 3×252训练子窗
→ 全部36候选按历史子窗评估，门禁失败则现金
→ 将每个方法的参数、cutoff、OOS起止、lock_hash事务提交
→ 此后才打开本窗口SQL游标
→ 一根已完成行情进入7-stage链
→ 旧订单按当前开盘价与上一根已完成成交量成交
→ 仅用截至当前收盘的信息更新指标、信号及未来订单
→ 所有方法/压力场景各自记账，推进下一根
→ 独立发布当前窗口，再读取下一窗口的历史
```

实现允许在编排层收到当前完成行情后处理其中开盘事件，但成交函数只能使用旧订单、current open、previous completed volume；本根close/high/low/最终volume不会决定本根开盘成交。测试通过扰动这些未来字段验证开盘成交不变。

训练特征缓存只覆盖已知训练窗，按参数配置复用；策略回放仍按每根历史特征顺序计算。测试/压力区间不预先计算整段指标、不把完整后续数组交给策略。数据库物理上存在未来行情不是策略可读权限；适配器对每次查询施加截止水位和holdout门禁。

训练目标：`median(Sharpe) - std(Sharpe) - 2*worst_DD`；至少2/3训练子窗收益为正、median Sharpe>0、最大回撤≤35%、累计成交≥6；并非最高历史收益。每个方法各选一个候选，失败则预声明现金，不强行选择“最不差”。排序相同按候选ID确定，结果可重复。

跨窗口保留真实账户现金、持仓、未到期订单；窗口边界不重置100000、不强制清仓。新参数在窗口前锁定，但不能取消已承诺的旧订单；新收盘信号按正常延迟生效。

基准：每标的独立100000初始资金、首个有效信号之后开盘买入约95%，以后不再平衡股数。方法/基准聚合均为八个独立现金账户权益相加，日历必须完全对齐；不是共享保证金组合，也没有隐含再平衡。

执行：单边手续费5bps、单边不利滑点5bps、延迟1根、上一完整交易日成交量的1%上限、整股、无借款/借券，新买入按费用后开盘权益限制至95%。已有仓位因价格变化超过目标不等于有保证实时调仓；部分成交余量到期，下次信号可重下单。压力场景预声明为成本翻倍和延迟2根。

正式保留每根权益/成交、base场景逐根决策、每窗口末根七阶段Envelope与全部阶段checkpoint、每候选每训练子窗汇总、锁参/查询/评审。**不宣称每一根都保存七套大对象**；这正是减少无效重复序列化和零散输出的治理边界。

制品+检查点成批事务发布；父制品不存在即回滚。同内容重试幂等；同键不同状态拒绝。窗口结果发布不是整个研究的单一超长事务；中途失败保留已完成窗口，study标FAILED，不能假装全程完成。SQLite外键/WAL/BEGIN IMMEDIATE复用既有连接规则；市场读取是独立只读事务快照，结果写入仍在同一个库。

`verify`独立检查：候选/子窗/锁/结果数量、参数摘要、锁提交早于OOS游标打开、查询holdout隔离、训练截止、决策摘要、延迟成交、费用非负、逐笔现金/仓位/权益账本、跨窗资金连续、阶段谱系及版本、阶段/汇总指标一致。它不是交易所数据源、公司行动或实盘成交质量认证。

## 6. 单阶段与整体运行

安装后用 `research-stages`；未安装可在项目根令PYTHONPATH=src，使用 `python -m inv_trend.cli.分阶段研究_v1`。发行包中的已有study_id不可重用；新实验示例：

```bash
research-stages --data data study --study-id 本地滚动验证_v4
research-stages --data data verify --study-id 本地滚动验证_v4
research-stages --data data report --study-id 本地滚动验证_v4 --output 本地研究评审_v4.html
```

`study`先运行随包定向pytest门禁，失败则不进入研究。报告从权威数据库投影，显式导出文件不得覆盖已有文件。

独立阶段示例：

```bash
research-stages --data data stage --stage acquire --symbol QQQ \
  --before 2024-01-03T22:00:00+00:00 --run-id 单阶段演示_v1
# 以下<上一步artifact_id>分别替换为上一条实际返回值；不要把旧ID反复传入。
research-stages --data data stage --stage process --input-id <上一步artifact_id>
research-stages --data data stage --stage indicators --input-id <上一步artifact_id>
research-stages --data data stage --stage signal --input-id <上一步artifact_id>
research-stages --data data stage --stage backtest --input-id <上一步artifact_id>
research-stages --data data stage --stage evaluate --input-id <上一步artifact_id>
research-stages --data data stage --stage report --input-id <上一步artifact_id>
```

一个单根示例不具备策略预热，不应期待交易；连续执行要传入后续时点的数据及上一检查点，或直接使用研究驱动。独立指标/策略替换必须产出相同输入/输出类型并通过因果、参数及恢复测试，不能只维持同名CSV列。

## 7. 明确未验收的范围

原日报/旧回测并未全部接入本链路，原全量测试尚未全绿；文件级兼容入口保留不代表行为全验收。未完成真实借券、期货/永续资金费/合约规则、共享资金多资产组合、交易所精确半日/停牌日历、点时公司行动版本、退市及成分股谱系、分红/税费、逐笔盘口成交、外部未来纸上交易验证。金银因合约未认证排除，不用合成成本冒充成熟多资产实盘引擎。

2025-01-01起留出行情未进入本轮研究查询；项目过去是否使用过这些行情无法认证。QQQ 2020已在工程回归中检查，完整滚动区间是历史开发样本外流程验证，不宣称从未见过的最终盲测。源库状态RESEARCH_ONLY，故只能证明**所给快照内的软件因果性与结果可复算性**，不能证明原始历史行情本身不存在未来修订。
