## 2. Review 1：数据与指标口径

### 2.1 通过项

1. **宇宙数量正确**：QQQ 100 + SPY 100，去重 164；剔除未登记的 SPCX 后 163，与页面一致。
2. **0 失败**：`failed=[]`，163 行全部有值；没有用假数据补失败标的。
3. **公式来源正确**：脚本使用 `FeatureRequest` + `PreparedBars`，没有自己重写指标。
   - SMA：`rolling(period, min_periods=period).mean()`，lag 0；
   - EMA：`ewm(span=period, adjust=False)`；
   - MACD：`DIF=EMA12-EMA26`，`DEA=EMA9(DIF)`；
   - ADX/DMI：Wilder 平滑，14 周期；
   - ATR：Wilder ATR，14 周期；
   - 通道：`rolling(period).max().shift(1)`，即前 N 根，不含当前根。
4. **MU/SNDK 的方向结论在“含最后一根”和“剔除最后一根”下都成立**：三对 EMA 全空、MACD 空；两只相对量都低于 1.5。结论本身没有因为盘中 bar 翻转，但数值不可当收盘值。

### 2.2 问题清单

| ID | 级别 | 问题 | 证据 | 影响 |
|---|---|---|---|---|
| R1-01 | P0 | 最后一根日线是盘中未收盘快照 | 文件生成于 2026-10-28 00:09 +08 = 2026-10-27 12:09 ET；最后一根 timestamp 为 2026-10-27 13:30 UTC（美股开盘）；页面 JSON：MU 相对量 0.3789、SNDK 0.4522；12:30 ET 复拉：MU 0.4043、SNDK 0.5001；剔除最后一根：0.8433 / 0.8314；MU 收盘 932.695（复拉 932.78）vs 完成 bar 903.70；HONA 0.2258 vs 1.0310 | “收盘”不是收盘；ADX/EMA/相对量都是盘中值；同一页面在不同时刻重跑数值会漂移；SNDK ADX 在 20 分钟内从 JSON 的 25.7862 变成 25.6523 |

| R1-08 | P1 | ADX/DMI 只展示 ADX | JSON 有 `plus_di`/`minus_di`，详情只显示 ADX、DIF、DEA、ATR | 无法判断多头/空头趋势方向；DMI 只算了一半 |

### 2.3 关键证据：盘中 bar 的影响

| 标的 | 含最后一根（页面） | 剔除最后一根（完成 bar） | 差异 |
|---|---|---|---|
| MU 收盘 | 932.695（JSON；复拉 932.78） | 903.70 | +3.2% 的盘中价被当成收盘 |
| MU ADX | 29.4581 | 29.5676 | 基本不变 |
| MU 相对量 | 0.3789（JSON；复拉 0.4043） | 0.8433 | 被压低约 55% |
| SNDK 收盘 | 1304.74（JSON；复拉 1315.35） | 1255.58 | +3.9% |
| SNDK ADX | 25.7862（JSON；复拉 25.6523） | 25.1858 | 盘中漂移 0.13–0.60 |
| SNDK 相对量 | 0.4522（JSON；复拉 0.5001） | 0.8314 | 被压低约 46% |
| HONA 相对量 | 0.2258 | 1.0310 | 被压低约 78% |
| HONA SMA120 | `None` | `None` | 94 根，预热不足 |

163 只的相对量分布也印证了这一点：

- 中位数 0.2971；
- 均值 0.3660；
- ≥1.5 的只有 2 只；
- ≥1.0 的只有 4 只。

完整交易日的相对量中位数应在 1.0 附近。当前分布不是市场特征，而是“盘中半天成交量 ÷ 全天均量”的结果。

### 2.4 Review 1 结论

公式没有错，**数据边界错了**。在修完 R1-01、R1-02、R1-03、R1-04 之前，页面上的“收盘、ADX、相对量”只能视为盘中快照，不能作为日线收盘结论，也不应拿 MU/SNDK 的具体数值做跨日比较。

## 7. 完善方案

### 7.1 总体思路

保留单文件页面和现有交互，不引入前端框架、不建后端服务。只改三件事：

1. **数据入口**：从 `_bars` 切到 `normalize_bars` + `PreparedBars`，接回仓库口径。
2. **数据模型**：JSON 从“页面字段”升级为“可审计快照”，页面只消费快照。
3. **页面表达**：把来源、盘态、预热、完整指标和免责声明说清楚。

推荐路径是“轻量接回”，不是“全量入湖”：

- 本次是一次性研究看板，不需要 `dataset_version`/curated parquet；

### 7.3 Phase 1：数据层（P0）

#### 1）完整性与数据截止

用仓库已有函数替换 `_bars` 的完整性判断：

```python
from inv_trend.data.calendar import latest_completed_us_bar
from inv_trend.data.processing import normalize_bars

cutoff = pd.Timestamp("2026-10-27 20:00", tz="UTC")  # 或 --as-of 传入
normalized = normalize_bars(
    fetched.frame, instrument, "D1", provider.name, now=cutoff.to_pydatetime()
)
clean = normalized.clean
completed = clean.loc[clean["is_complete"].astype(bool)]
```

要点：

- `normalize_bars` 已按 `bar_end <= now` 计算 `is_complete`，不要自己写日期判断；
- 默认 `completed_only=True`；`--include-partial` 才保留最后一根，并在 JSON 和页面标 `partial=true`；
- `latest_completed_us_bar` 可用于默认 cutoff，避免手写美股收盘时间（夏令时 20:00 UTC、冬令时 21:00 UTC）。

#### 2）不再补假数

删除 `volume.fillna(0)`：

- 缺失 volume 保持 `NaN`；
- `relative_volume` 为 `None`，页面显示“—”；
- 在回执中记录 `volume_missing_count`；
- 用 `normalized.quarantine` / `normalized.audit` 记录被隔离的行和原因，不再静默 `dropna`/`drop_duplicates`；
- 记录 `duplicate_count`、`ohlc_anomaly_count`、`conflicting_duplicate_count`。

#### 3）复权

按仓库 `load_bars(adjusted=True)` 的同一逻辑，在脚本内做 3 行因子乘法，不改产品代码：

```python
if instrument.asset_class == "equity" and "adjusted_close" in frame:
    factor = frame["adjusted_close"] / frame["close"]
    for column in ("open", "high", "low", "close"):
        frame[f"unadjusted_{column}"] = frame[column]
        frame[column] = frame[column] * factor
```

要点：

- 指标用复权 OHLC；
- 页面“收盘”显示 `unadjusted_close`，另列“复权收盘”或“复权因子”；
- 回执写 `price_basis: provider_adjusted_close`；
- 不要用 `adjusted_close` 直接替换 close 后忘记保留原始价，否则页面价格与行情软件对不上。

#### 4）预热与“算不出”清单

```python
MIN_BARS = max(169, 120, 2 * 14 + 1)  # 169
warmup_ok = len(completed) >= MIN_BARS
```

- 不足 169 根：`warmup_ok=false`；
- `sma_120`/`ema_144`/`ema_169` 若为 `NaN` 或未充分预热，页面显示“预热不足”，不显示具体数值；
- 新增 `incomplete` 列表：`symbol, bar_count, missing_fields, reason`；
- 当前 HONA 94 根，应进入该列表，而不是只让 SMA 列显示“—”。

#### 5）本地优先与缓存

每个标的三步：

1. 先查本地 lake：`HistoricalDataService.load_bars(symbol, "D1", start, end, allow_research=True, completed_only=True)`；
2. 本地没有或 `--refresh` 才拉 Yahoo；
3. 拉到的原始 JSON 写入 `.cache/yahoo/<cutoff_date>/<symbol>.json`，记录 `sha256`；重跑优先读缓存，保证同一 `--as-of` 结果一致。

注意：

- 缓存目录放 `.tmp/` 或用户缓存目录，不进 git；
- 回执记录 `source: local|yahoo_cache|yahoo_live`，页面可显示“数据源”；
- 163 只逐个拉取，保留现有 `retries`；并发作为 P2，不要在第一版引入限流风险。

## 9. 风险与非目标

### 9.1 风险

| 风险 | 说明 | 处理 |
|---|---|---|
| Yahoo research-only | `YahooChartProvider` 标注 research-only，非机构级行情 | 页面明示；不用于交易执行；后续可换授权源 |
| 复权因子非机构公司行动序列 | 仓库质检注释已说明 provider adjusted-close 不是“verified institutional corporate-action series” | 页面写 `price_basis`；不宣称精确复权 |
| 幸存者偏差 | 用 2026-10-23 的当前成分回看 120 日，不是历史成分 | 明确“当前成分快照，不是回测” |
| 名单不可验证 | QQQ/SPY 名单硬编码，未附官方文件 | 宇宙 JSON + source/retrieved_at |
| SPCX 剔除 | 未登记，QQQ 实际 99 个 | 页面写“QQQ 99/100，SPCX 剔除” |
| HONA 94 根 | 新上市/分拆，EMA169 未预热 | `warmup_ok=false` + incomplete 清单 |
| 双份额类别 | GOOG/GOOGL 同时保留 | 页面注“按代码去重” |
| 限流 | 163 只逐个拉取 | 缓存 + retries；并发作为 P2 |

### 9.2 非目标

- 不做实时/盘中交易信号；
- 不做买卖建议或仓位建议；
- 不把当前成分当成历史成分做回测；
- 不引入前端框架、后端服务、数据库；
- 不改 `PreparedBars` / `normalize_bars` 的公式；
- 不在本次强行把 163 只全部入湖；入湖作为后续可选项；
- 不承诺 163 只永久不变，宇宙按快照更新。
