# 模块依赖契约 v1

> 本文件与 `tests/test_architecture_boundaries.py` 的 `DECLARED_PACKAGE_EDGES` /
> `KNOWN_PACKAGE_CYCLES` 一一对应：代码是权威，文档是解释。任何新增跨包依赖都会使
> 该测试失败，必须显式评审后追加。

## 1. 目标分层

依赖只允许由上层指向下层（同层之间按既有约定）。

| 层 | 包 | 职责 |
|---|---|---|
| L0 | `domain`、`config` | 纯领域契约、配置装载（零内部依赖） |
| L1 | `core` | 纯计算与因果特征；禁止 `data`/`application`/`observability`/`adapters` |
| L2 | `ports` | **新增**：跨层接口（Protocol + 纯 DTO），只允许依赖 `core` |
| L3 | `data` | 行情采集、目录/血缘、时点数据 |
| L4 | `storage` | 版本化仓库、制品、迁移、生命周期 |
| L5 | `observability` | 纯渲染（HTML/JSON 展示），禁止依赖 `data`/`adapters` |
| L6 | `adapters`、`integrations` | 六边形边界适配器（检测器、多资产、日更发布、MT5/OKX） |
| L7 | `application` | 用例编排（日更、回测、研究、永续审计） |
| L8 | `monitoring` | 长时监督、看板、回放 |
| L9 | `notifications` | 通知队列与渠道 |
| L10 | `cli` | 组合根与命令入口 |

## 2. 现行包级依赖（35 条边）

```
ports      -> core
adapters   -> config, core, data, domain, observability, ports
application-> adapters, config, core, data, domain, ports, storage
observability -> core
storage    -> core, data
data       -> core, storage
integrations -> adapters
monitoring -> adapters, core, data, observability
notifications -> monitoring, observability
cli        -> adapters, application, config, core, data, monitoring,
              notifications, observability, storage
```

## 6. 已知残余与后续建议

**唯一残余循环：`data ↔ storage`。**
`data` 侧 5 个模块需要 v3 目录原语（`UnifiedStore`/`CatalogPath`/`DB_RELATIVE`/`utcnow`/
`canonical`/`digest`/`StoreError`/`normalize_ref`），而该原语簇位于 `storage`，且簇内部
互相耦合：

- `storage/结构化存储_v3.py` 在 `CatalogPath.exists()` 内惰性 import `研究结果_v3.ResultRepository`；
- `storage/数据生命周期_v3.py` 惰性 import `研究结果_v3`；
- `storage/阶段制品.py` 依赖 `storage/基础.py` 与 `storage/仓库.py`。

因此“把原语簇整体下移”会连带 `研究结果_v3 → 阶段制品 → 仓库` 等 6 个以上模块，
超出本轮“控制改动范围”的预算，故未执行。两条可选的后续路径：

1. **簇内反转**：把 `CatalogPath.exists()`/`生命周期` 对 `ResultRepository` 的惰性依赖改为
   由 `研究结果_v3` 注册的探针（约 6 行），再单独下移 `结构化存储_v3`；
2. **整簇迁移**：把该 v3 存储簇整体移到独立包（如 `inv_trend/catalog/`），
   `storage` 与 `data` 都改为向下依赖它。

两者都需先确认对历史制品/数据库读取路径无影响，再按独立提交推进。

**外层残余方向**（属目标分层允许，已由 `DECLARED_PACKAGE_EDGES` 固定，不得新增）：
`monitoring → adapters/observability`、`notifications → monitoring/observability`、
`integrations → adapters`、`adapters → observability`（下行：`observability` 只做渲染，
且已被禁止依赖 `data`/`adapters`）。

## 7. 复核方式（每阶段提交前）

1. **等价性**：逐行 diff + 搬动入口的 digest A/B（列名/dtype/数值哈希一致）。
2. **接口与调用方**：全仓库检索被搬动符号的全部引用（含 `TYPE_CHECKING`、字符串注解、
   `__import__`/`import_module`、测试与脚本），并运行 `scripts/遗留模块引用审计.py`。
3. **反向对抗**：重新计算包级边与循环集合，确认 I1–I5 成立且计数单调收敛；
   同时跑全量回归与 `tests/test_golden_master.py`。
