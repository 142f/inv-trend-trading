# 永续策略审计实施说明

## 运行与当前证据

```powershell
.venv/Scripts/python.exe scripts/永续策略重新审计.py --download
.venv/Scripts/python.exe scripts/永续策略重新审计.py
.venv/Scripts/python.exe -m pytest -q tests/test_永续研究协议.py tests/test_永续分钟执行.py
```

默认产物位于 `outputs/永续策略审计`，行情原始页和采集清单位于 `data/永续审计`。
采集从最新完整研究截止时间逆向翻页直到端点耗尽，不人为截取最近几年。
端点耗尽不等于证明上市以来历史完整。`--max-pages` 仅用于调试，结果标为 TRUNCATED。
代码不读取 OKX 私钥，也不调用真实下单接口。

当前工作环境的八个行情请求均返回连接错误，真实合约实验尚未运行。
输出的 E0 是数据证据结论，不是已经完成真实回测后对策略收益的结论。
历史未见性没有独立证明，测试期默认 CONTAMINATED_TEST。

## 三条代码边界

- `core/永续风控.py`：历史规格、实际止损风险、逐仓状态机、资金费及正常/压力波动纯函数。
- `application/perpetual_audit`：冻结协议、历史资格、分钟事件回放、实验登记、统计、归因及报告。
- `data/永续历史.py`：无需私有凭据的 OKX 公共历史采集、原始页哈希和覆盖审计。

旧的日线回测器保持原有语义；新永续回放显式独立。每日与回测复用的资格确认函数
保留 status=PASSED、evaluated=true、passed=true 三项要求，未放宽旧生产闸门。
OKX 接口默认逐仓、内部最多3倍，环境变量超过3倍明确报错；交易所实际限制仍可能更低。

## 数据恢复后的认证输入

仅下载价格不能认证资金费完整性或历史仓位档位。在数据根目录提供 `认证输入.json`，
协议为 `perpetual-input-v1`。每个输入引用必须有 `file`、`sha256`、`source`。
文件引用只能位于该数据根目录内；哈希、UTC日历、OHLC及规格有效区间均验证。

```json
{
  "schema_version": "perpetual-input-v1",
  "instruments": {
    "BTC-USDT-SWAP": {
      "daily": {"file": "BTC/日线.parquet", "sha256": "实际文件SHA256", "source": "OKX证据地址"},
      "minute": {"file": "BTC/分钟.parquet", "sha256": "实际文件SHA256", "source": "OKX证据地址"},
      "marks": {"file": "BTC/标记分钟.parquet", "sha256": "实际文件SHA256", "source": "OKX证据地址"},
      "funding": {
        "file": "BTC/资金费.parquet", "sha256": "实际文件SHA256", "source": "OKX证据地址",
        "coverage_start": "带UTC时区的实际覆盖开始", "coverage_end": "带UTC时区的实际覆盖结束",
        "settlement_schedule_evidence": "独立结算事件完整性核对记录"
      },
      "specs": {"file": "BTC/历史规格.json", "sha256": "实际文件SHA256", "source": "历史公告与档位证据"}
    },
    "ETH-USDT-SWAP": "与BTC相同的引用结构，必须使用ETH自己的文件与证据"
  },
  "eligibility_context": []
}
```

这只是字段说明，含占位符，不可直接作为认证文件使用。
行情表含 `timestamp,open,high,low,close,volume`；标记价格也采用 OHLC。
资金费含 `timestamp,funding_rate,mark_price_at_event,source`，时间戳来自实际结算事件。
不根据00/08/16点推算事件；没有独立事件完整性证据不能自动认证。

历史规格是 InstrumentSpec 字段的JSON数组，每条包括 instrument、两个版本号、
effective_from、effective_to、source、spec_status、contract_value、lot_size、minimum_size、
exchange_max_leverage、fee_rate、liquidation_fee_rate、tiers。
tiers 的字段为 notional_cap、maintenance_rate、max_leverage。
只有真实历史证据才使用 VERIFIED_HISTORICAL，其他必须使用 SIMULATED_SPEC。
未支持持仓中的合约面值转换；遇到转换明确失败，不偷换单位。

完整每日资格使用现有 TradeEligibilityChecker。外部历史上下文项包含
instrument、available_at、effective_from、effective_to、source、backtest_validated、execution_ready。
上下文缺失时不能确认资格；仓位、权益和回撤由本次回放状态重算。
不能把本轮候选回测结果当作当时已经获得的 backtest_validated。

## 日期划分

最早连续日线开始的440日用于预热，完整执行开始还受分钟、标记价格、资金费和规格覆盖限制。
从首个可评价日S起训练730日，之后每180日一个扩展训练验证折。
不足3折不缩短规则；尾段单列；2026-04-21—2026-09-06只有证明未参与研究才可称UNSEEN_TEST。
输出的实际区间表只填写已核实数据；没有数据时保留空表，不填条件示例冒充实测。

以下日期仅说明固定算法，**不是已取得的数据范围**。前提是S=2022-03-01且之前440日预热齐全：

|折次|扩展训练|验证|
|---|---|---|
|1|2022-03-01—2024-02-28|2024-02-29—2024-08-26|
|2|2022-03-01—2024-08-26|2024-08-27—2025-02-22|
|3|2022-03-01—2025-02-22|2025-02-23—2025-08-21|
|4|2022-03-01—2025-08-21|2025-08-22—2026-02-17|

开发尾段2026-02-18—2026-04-20；拟测试期2026-04-21—2026-09-06。
若S=2023-07-01，则训练到2025-06-29，仅有2025-06-30—2025-12-26一个完整验证折，不能提高证据等级。

## 模型的实际限制

- 两条OHLC顺序轨道会持续回放，但不是所有可能盘内路径的数学上下界。
- 同时资金费/订单按两种顺序计算即时权益，选择不利/有利路径继续；不能保证全期全局极值。
- 毫秒内资金费若没有逐笔数据，分钟回放拒绝执行；不会用分钟极值伪造毫秒排序。
- 逐仓分档减仓采用档位容量模拟规则，未复现交易所排队、清算拍卖、订单簿冲击或ADL。
- 历史输入认证与执行模型精度分开；SIMULATED_SPEC不能通过正式真实性门槛。
- DSR保留IID近似限制；成对块bootstrap另处理部分时间依赖，二者不能证明未来必然盈利。
- 去掉最大赢家仅是固定账本诊断，不是可执行策略，也未重算随后资金路径。
- 纸面观察从实际启动起记录，不能把历史回放写成90日前向执行。

## 研究输出与验收

全部中心候选、失败、调试及复验记录追加到实验登记，失败组合不隐藏。
默认只有中心可被选择，邻域是DIAGNOSTIC_ONLY；新测试失败不换候选。
旧现货、原风险合约、统一风险预算合约分别保存。
训练、独立重置验证窗口、连续开发曲线、双倍成本、双场景及后续测试分别输出。

对照指标包括收益、回撤、Sharpe、Calmar、胜率、盈亏比、交易数、集中度和参数邻域稳定性。
30笔只是最低分析门槛。正式升级要求预登记的绝对门槛、相对基线改善和置信区间同时支持。
当前输出E0；独立测试及纸面证据需要真实新增数据，程序不会自动将开发支持升级为实盘可用。
