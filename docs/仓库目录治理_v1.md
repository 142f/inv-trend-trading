# 仓库目录治理 v1

本文件是目录职责与清理流程的现行规范。迁移记录见
[迁移清单](../artifacts/history/docs/迁移清单_20261103.md) 与
[目录收敛清单](../artifacts/history/docs/目录收敛清单_v1.md)。

## 顶层职责

| 目录 | 只放 | 不放 |
| --- | --- | --- |
| `src/` | 唯一可维护实现（含 `observability/静态展示/pages/` 固定展示资源） | 脚本、样本数据、一次性验收产物、`__pycache__` |
| `tests/` | 正式测试与夹具 | 一次性核验脚本 |
| `scripts/` | 可重复运行的运维、核验、研究入口 | 已完成且无引用的一次性脚本 |
| `research/` | 可复现研究 | 运行结果（结果进 `research/**/outputs/`，且不入库） |
| `config/`、`execution/` | 版本化配置与执行规格 | 本机覆盖、密钥 |
| `docs/` | 现行规范 | 一次性验收 JSON、补丁、历史证据 |
| `data/` | 权威数据根：`raw/`、`processed/`、`features/`、`signals/`、`backtests/`、`metadata/` | 源码、临时导出、缓存 |
| `processed_data/` | 流水线阶段产物：`raw_index/`、`cleaned/`、`merged/`、`backtest_ready/`、`logs/`、`metadata/` | 与 `data/` 重复的第二份权威副本 |
| `outputs/` | 按一次运行归档的证据（`outputs/<运行ID>/`） | 散落在仓库根的回执、日志 |
| `artifacts/` | 无运行入口的一次性审计快照与历史归档 | 产品页面 |
| `deliverables/` | 对外静态交付（已忽略） | 源码与权威数据 |
| `.tmp/` | 本次任务的中间文件，用完即删 | 任何需要留存的结果 |

历史证据归档在 `artifacts/history/`：`docs/` 保持现行规范，`scripts/` 保持可重复入口。
一次性规划与方案文档（例如原 `.trae/documents/`）同样归档到 `artifacts/history/docs/`，
不在仓库根保留隐藏的规划目录。

## 读写规则

1. 程序只从 `src/` 读实现，从 `config/` 与 `execution/` 读规格，从 `data/` 或
   `processed_data/` 读数据。
2. 写入分四类：权威数据进 `data/`；阶段产物进 `processed_data/`；一次运行的证据进
   `outputs/<运行ID>/`；中间文件进 `.tmp/`。
3. 同一份数据只留一个权威位置。`processed_data/` 能引用 `data/` 或上一级阶段文件时，
   写清单，不再复制一份。
4. `data/metadata/研究目录_v3.sqlite3` 是目录权威。旁边的 `-wal`、`-shm` 是数据库
   运行文件，不单独当垃圾删除。
5. `.env*` 只存本机覆盖与密钥，不放入 `config/`、`execution/`。

## 迁移流程

1. 盘点：列出原路径、目标路径、理由、全仓库引用（导入、配置、脚本、文档、测试）。
2. 归档优先：能移动的先移动，不先删除。一次性脚本与历史证据移到
   `artifacts/history/`，永久保留。
3. 更新引用：所有运行中入口（源码、测试、配置、脚本、README、现行规范）必须改到
   新路径；历史归档内记录的原路径按当时状态保留。
4. 删除：仅在引用核对完成且确认无引用后，删除一次性文件、冗余副本与中间产物。
5. 退役兼容路径必须注明退役条件，不能只留一句“兼容”。

## 缓存清理

缓存只通过 `scripts/目录治理_v1.py` 清理：

```bash
python scripts/目录治理_v1.py --root . --manifest .tmp/清理清单_v1.json
# 审阅清单中的路径与 SHA-256，确认后执行：
python scripts/目录治理_v1.py --root . --manifest .tmp/清理清单_v1.json --apply
```

范围限于 `__pycache__/`、`*.pyc`、`build/`、`*.egg-info/`、`.pytest_cache/`。
清理前必须停止测试与构建写入；`--apply` 会逐个核对路径与哈希，任一文件变化即整批停止。
`.git/`、`.venv/` 与 `.ruff_cache/` 永不进入清单。

## 不删除、不移动

- `data/` 与 `processed_data/` 的业务文件；
- `.env`；
- 仍被导入或文档引用的模块；
- 被验收证据点名的 `outputs/` 路径；
- 看不出用途的文件：保留并在迁移清单里标明。

## 保留例外

- `processed_data/us_trend_alerts/cache/`：`us_trend_alerts` 的代码默认缓存，保留。
- `data/metadata/目标迁移备份_*.sqlite3`：迁移备份，属于 `data/` 业务文件，保留。
- `.ruff_cache/`：不在授权清理范围，保留。
- `deliverables/`、`outputs/`、`data/`、`processed_data/` 的内容不入库，只跟踪各自
  `README.md`。
