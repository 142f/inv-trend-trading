# 独立策略回测阶段 v1

> 本文档为历史只读说明。新代码和命令请参见 `统一回测模块_v2.md`；v1 结果可通过
> `strategy-backtest report` 转换为统一 HTML，转换过程不会重新运行策略。

策略回测阶段读取已经发布的日报批次、其中记录的数据版本和策略结果哈希。它不会写入
SignalStore、通知 outbox 或规范策略配置，也不会修改来源批次。

## 命令

```powershell
turtle-backtest validate-plan `
  --plan config/策略回测计划_BTC_ETH_v1.yaml `
  --source-run outputs/daily_market_scan/runs/2026-08-27/<批次>

turtle-backtest run `
  --plan config/策略回测计划_BTC_ETH_v1.yaml `
  --source-run outputs/daily_market_scan/runs/2026-08-27/<批次> `
  --data-root data `
  --output-dir outputs/strategy_backtest
```

同一能力也可以通过 `turtle-daily backtest` 调用。完整日报可使用
`--with-backtest --backtest-plan <文件>` 在发布和通知完成后追加回测；追加阶段失败不会回滚
日报和正式信号，但命令会返回非零状态以便任务系统发现问题。

## 参数与可比性

- `turtle.rules.*` 改变策略规则；只影响成交和风控的参数不会触发指标重新准备。
- `assets.<标的>.*` 可调整仓位和合约约束；手续费和滑点故意禁止作为同批次搜索维度。
- v1 对不直接进入现有多资产执行器的 `daily_screening.*` 参数采取失败关闭，避免展示一组
  实际没有改变成交结果的伪参数。后续若搜索评级参数，必须先为其提供正式信号到订单意图的
  明确映射。
- 所有组合必须绑定相同数据版本、时间切分、初始资金、现金模型和成交口径。
- 信号在当根完整 D1 收盘形成，订单从下一根可交易 K 线开盘起才可成交。
- `constraints` 使用只包含参数名、常量、比较和布尔运算的表达式，不执行函数或任意代码。

## 选优解释

默认执行扩展窗口前推验证，最终 252 根为一次性留出集。综合分只使用验证折；留出集为负
时不会输出最优参数。历史不足以形成三个验证折时仍生成全样本诊断，但
`best_combination_id` 和稳定区间保持为空。报告中的 0–100 分表示横向证据强度，不代表
未来胜率或盈利概率。
