# 回测模块清理审计 v2

## 依赖检查与处置

| 原实现 | 检查到的依赖 | 处置 |
|---|---|---|
| `application/strategy_backtest` | CLI、日报附加阶段、单元测试 | 实现迁入 `application/backtest`；原路径保留无业务逻辑的弃用转发层 |
| `application/backtest_service.py` | 应用服务测试、历史研究调用 | 实现迁入统一模块；原文件仅保留一版兼容类 |
| `observability/backtest_html.py` | 核心数据构建 | 删除旧模板；改为统一 HTML 渲染器转发 |
| 研究脚本 `write_backtest_outputs` | 多个 D1 研究入口 | 保留函数签名，内部统一调用 `single_artifacts`，删除重复写盘逻辑 |
| 核心数据构建的 `export_backtest_outputs` | `turtle-data build-metal-tech-core` | 保留调用面，内部统一调用同一制品写入器 |
| `DetectorBacktester` | Detector 测试、黄金主 | 改名为 `ChronologicalSignalValidator`；旧名只保留弃用别名 |
| `TurtleBacktester` | 底层执行测试和应用执行门面 | 作为 adapters 层低级引擎保留，不属于重复实现 |

## 历史产物策略

- 正式历史回测批次全部保留，不重算、不覆盖、不删除。
- 新输出根目录会自动生成历史只读归档索引。
- 未跟踪且无法确认归属的研究文件不删除。
- 仅允许删除名称和位置均明确属于 smoke/tmp 的产物；删除前必须验证目标位于工作区临时目录，
  且未被 latest、测试、文档或审计清单引用。
- 本次已删除 `.tmp/策略回测冒烟` 的 145 个临时文件及一份 v1 报告转换临时文件；
  `outputs` 下的正式和历史回测批次均未删除。

## 回归门槛

- 整理前 BTC/ETH 最佳组合基线保存在 `tests/fixtures/回测整理前基线_v1.json`。
- 订单、交易和权益分别校验哈希，联合校验 `execution_result_hash`；整理前随机生成的
  `intent_id` 属于操作身份，规范化比较时排除，新执行已改为确定性 ID。
- 核心交易结果必须完全一致；派生浮点指标允许的最大误差为 `1e-12`。
- 兼容入口必须产生 `DeprecationWarning`，同时保持旧返回结果和文件语义。
